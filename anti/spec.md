# 申請管理システム 機能仕様書

**バージョン**: 1.0  
**作成日**: 2026-08-21  

---

## 非機能要件

本システムは社内業務用の小〜中規模Webアプリケーションとして設計する。

| 項目 | 要件 |
|-----|------|
| 対象規模 | 社内利用、最大50名程度 |
| パフォーマンス | 通常操作時のレスポンスタイムは5秒以内（同時接続10ユーザー想定） |
| セキュリティ | HTTPS通信、パスワードのbcryptハッシュ化、SQLインジェクション対策、XSS対策 |
| 可用性 | 業務時間内（平日9〜18時）に安定稼働すること |
| ブラウザ対応 | Chrome / Edge 最新版 |
| データ量 | 年間申請件数 数千件程度を想定 |

## F-001: ユーザー登録

### 概要
新規ユーザーがシステムに登録するための機能。

### 前提条件
- 管理者権限を持つユーザーがログイン済みであること（管理者が代理登録する場合）
- または、公開登録フォームからの自己登録であること

### 入力

| 項目 | 型 | バリデーション |
|-----|---|--------------|
| 氏名 | 文字列 | 必須、最大50文字 |
| メールアドレス | 文字列 | 必須、メール形式、システム内で一意 |
| パスワード | 文字列 | 必須、8文字以上、英数字混在 |
| パスワード確認 | 文字列 | 必須、パスワードと一致 |
| 所属部署 | 文字列 | 必須、最大100文字 |
| 役職 | 選択肢 | 必須（一般・課長・部長・管理者） |

### 処理内容

1. 入力フォームを表示する。
2. ユーザーが各項目を入力し、「登録」ボタンをクリックする。
3. サーバー側で入力値のバリデーションを実施する。
4. メールアドレスの重複確認を行う。
5. パスワードをハッシュ化（bcrypt）して保存する。
6. ユーザーレコードをDBに登録する（ステータス: 有効）。
7. 登録完了メールを登録メールアドレスへ送信する。
8. 登録完了画面を表示する。

### 出力・結果
- ユーザーアカウントが作成される。
- 登録完了メッセージが表示される。
- 登録完了メールが送信される。

### エラー条件

| エラー | メッセージ |
|-------|----------|
| 必須項目未入力 | 「{項目名}を入力してください」 |
| メール形式不正 | 「有効なメールアドレスを入力してください」 |
| メールアドレス重複 | 「このメールアドレスは既に登録されています」 |
| パスワード不一致 | 「パスワードが一致しません」 |
| パスワード強度不足 | 「パスワードは8文字以上で英字と数字を含めてください」 |

## F-002: ログイン・ログアウト

### 概要
登録済みユーザーがシステムにログインおよびログアウトする機能。

### 前提条件
- ユーザーがシステムに登録済みであること。
- ユーザーアカウントが有効状態であること。

### 入力（ログイン）

| 項目 | 型 | バリデーション |
|-----|---|--------------|
| メールアドレス | 文字列 | 必須、メール形式 |
| パスワード | 文字列 | 必須 |

### 処理内容（ログイン）

1. ログイン画面を表示する。
2. ユーザーがメールアドレスとパスワードを入力し「ログイン」ボタンをクリックする。
3. 入力値のバリデーションを実施する。
4. DBからメールアドレスに一致するユーザーを検索する。
5. パスワードのハッシュ照合を行う。
6. 連続ログイン失敗回数を確認する（5回失敗でアカウントロック）。
7. 認証成功時、セッションを生成しダッシュボードへリダイレクトする。
8. 最終ログイン日時をDBに更新する。

### 処理内容（ログアウト）

1. ユーザーが「ログアウト」ボタンをクリックする。
2. サーバー側でセッションを破棄する。
3. ログイン画面へリダイレクトする。

### 出力・結果
- ログイン成功時: ダッシュボード画面が表示される。
- ログアウト成功時: ログイン画面へ遷移し「ログアウトしました」メッセージが表示される。

### エラー条件

| エラー | メッセージ |
|-------|----------|
| 認証失敗 | 「メールアドレスまたはパスワードが正しくありません」 |
| アカウントロック | 「アカウントがロックされています。管理者にお問い合わせください」 |
| アカウント無効 | 「このアカウントは無効です」 |

## F-003: 申請書の新規作成

### 概要
申請者が新規申請書を作成し、申請種別を選択する機能。

### 前提条件
- ユーザーがログイン済みであること。
- 申請種別がシステムに1件以上登録されていること。

### 入力

| 項目 | 型 | バリデーション |
|-----|---|--------------|
| 申請種別 | 選択肢 | 必須（経費申請・購買申請・その他） |

### 処理内容

1. ユーザーが「新規申請」ボタンをクリックする。
2. 申請種別選択画面を表示する。
3. ユーザーが申請種別を選択し「次へ」をクリックする。
4. 選択された申請種別に応じた入力フォームを生成する。
5. 申請書の入力画面を表示する（ステータス: 未保存）。

### 出力・結果
- 申請種別に応じた入力フォームが表示される。

### エラー条件

| エラー | メッセージ |
|-------|----------|
| 申請種別未選択 | 「申請種別を選択してください」 |

## F-004: 申請内容の入力・編集

### 概要
申請者が申請書の内容を入力または編集する機能。

### 前提条件
- ユーザーがログイン済みであること。
- 申請書が新規作成済み、または下書き状態であること。

### 入力

| 項目 | 型 | バリデーション |
|-----|---|--------------|
| 申請タイトル | 文字列 | 必須、最大100文字 |
| 申請金額 | 数値 | 必須、1以上9,999,999以下の整数 |
| 申請理由 | 文字列 | 必須、最大1000文字 |
| 添付ファイル | ファイル | 任意、PDF/Excel/Word/画像、各5MB以下、最大5件 |
| 申請日 | 日付 | 必須、システム日付以前は不可（当日以降） |

### 処理内容

1. 申請書入力フォームを表示する。
2. ユーザーが各項目を入力する。
3. 添付ファイルがある場合、ファイルのアップロード処理を行う。
4. 入力値のバリデーションをリアルタイムで実施する。
5. 「下書き保存」または「提出」ボタンをクリックする（次機能へ）。

### 出力・結果
- 入力内容がフォームに反映される。
- ファイルアップロード成功時、ファイル名が一覧に表示される。

### エラー条件

| エラー | メッセージ |
|-------|----------|
| 必須項目未入力 | 「{項目名}を入力してください」 |
| 金額範囲外 | 「申請金額は1円以上9,999,999円以下で入力してください」 |
| ファイル形式不正 | 「PDF、Excel、Word、画像ファイルのみアップロード可能です」 |
| ファイルサイズ超過 | 「ファイルサイズは5MB以下にしてください」 |
| ファイル数超過 | 「添付ファイルは最大5件までです」 |

## F-005: 申請の下書き保存

### 概要
入力途中の申請書を下書きとして保存する機能。

### 前提条件
- ユーザーがログイン済みであること。
- 申請書が入力中または下書き状態であること。

### 入力
- 申請書入力フォームの現在の入力値（F-004参照）

### 処理内容

1. ユーザーが「下書き保存」ボタンをクリックする。
2. 必須バリデーションを省略し、形式バリデーションのみ実施する。
3. 申請書レコードをDBに保存（ステータス: 下書き）。
4. 下書き保存日時を記録する。
5. 「下書きを保存しました」メッセージを画面上部に表示する。

### 出力・結果
- 申請書が下書き状態で保存される。
- 申請一覧に「下書き」ステータスで表示される。

### エラー条件

| エラー | メッセージ |
|-------|----------|
| 保存失敗 | 「保存に失敗しました。再度お試しください」 |

## F-006: 申請の提出（申請番号採番・承認者決定）

### 概要
作成した申請書を提出し、申請番号を採番、承認者を決定する機能。

### 前提条件
- ユーザーがログイン済みであること。
- 申請書が下書き状態または入力中状態であること。
- 全必須項目が入力済みであること。

### 入力
- 申請書入力フォームの入力値（F-004参照）

### 処理内容

1. ユーザーが「提出」ボタンをクリックする。
2. 全必須項目のバリデーションを実施する。
3. 申請金額に基づいて承認者を決定する。
   - 申請金額が **499,999円以下** → 承認者: **課長**
   - 申請金額が **500,000円以上** → 承認者: **部長**
4. 申請番号を採番する（形式: `REQ-YYYYMMDD-XXXX`、XXXXは当日の連番4桁）。
5. 申請書レコードをDBに保存（ステータス: 承認待ち）。
6. 提出日時を記録する。
7. 申請者に「申請を提出しました」メッセージを表示する。
8. 承認者へメール通知を送信する（F-014参照）。

### 出力・結果
- 申請書が「承認待ち」ステータスになる。
- 申請番号が採番・表示される。
- 承認者が確定し表示される。
- 承認者へ通知メールが送信される。

### エラー条件

| エラー | メッセージ |
|-------|----------|
| 必須項目未入力 | 「{項目名}を入力してください」 |
| 承認者未設定 | 「対象の役職を持つユーザーが存在しません。管理者にお問い合わせください」 |
| 採番失敗 | 「申請番号の採番に失敗しました。再度お試しください」 |

## F-007: 申請一覧表示

### 概要
ユーザーが自身の申請または承認待ち申請の一覧を表示する機能。

### 前提条件
- ユーザーがログイン済みであること。

### 入力
- なし（ページ遷移時に自動取得）

### 処理内容

1. ユーザーが「申請一覧」メニューをクリックする。
2. ログインユーザーの役割に応じて表示データを取得する。
   - 一般ユーザー: 自分が申請した一覧
   - 課長・部長: 自分への承認待ち一覧 + 自分が申請した一覧
   - 管理者: 全申請一覧
3. 申請日の降順でソートして表示する。
4. 1ページあたり20件表示（ページネーション）。

### 出力・結果
申請一覧が以下の列で表示される：

| 列 | 内容 |
|----|-----|
| 申請番号 | REQ-YYYYMMDD-XXXX |
| 申請種別 | 経費申請等 |
| 申請タイトル | タイトル文字列 |
| 申請金額 | 金額（円） |
| ステータス | 下書き/承認待ち/承認済み/差し戻し/取消 |
| 申請日 | YYYY/MM/DD |
| 承認者 | 承認者氏名 |

### エラー条件

| エラー | メッセージ |
|-------|----------|
| データ取得失敗 | 「一覧の取得に失敗しました。再度お試しください」 |

## F-008: 申請の検索・絞り込み

### 概要
申請一覧から条件を指定して検索・絞り込みを行う機能。

### 前提条件
- ユーザーがログイン済みであること。
- 申請一覧画面が表示されていること。

### 入力

| 項目 | 型 | バリデーション |
|-----|---|--------------|
| キーワード | 文字列 | 任意、最大100文字（申請番号・タイトル対象） |
| ステータス | 選択肢 | 任意（下書き/承認待ち/承認済み/差し戻し/取消/全て） |
| 申請種別 | 選択肢 | 任意 |
| 申請日FROM | 日付 | 任意 |
| 申請日TO | 日付 | 任意、FROM以降 |
| 申請金額FROM | 数値 | 任意、0以上 |
| 申請金額TO | 数値 | 任意、FROM以上 |

### 処理内容

1. 検索フォームに条件を入力し「検索」ボタンをクリックする。
2. 入力条件のバリデーションを実施する。
3. 条件に合致する申請をDBから取得する。
4. 検索結果を申請一覧形式で表示する。
5. 検索条件をURLパラメータに反映する（ブラウザバック対応）。

### 出力・結果
- 条件に合致する申請一覧が表示される。
- 件数が表示される（例:「3件見つかりました」）。
- 条件に合致する申請がない場合「該当する申請はありません」と表示。

### エラー条件

| エラー | メッセージ |
|-------|----------|
| 日付範囲不正 | 「申請日の終了日は開始日以降の日付を入力してください」 |
| 金額範囲不正 | 「申請金額の上限は下限以上の値を入力してください」 |

## F-009: 申請詳細表示

### 概要
申請書の詳細情報を表示する機能。

### 前提条件
- ユーザーがログイン済みであること。
- 対象申請書へのアクセス権限があること（申請者本人・承認者・管理者）。

### 入力
- 申請番号（URLパラメータ）

### 処理内容

1. ユーザーが申請一覧の申請番号または申請タイトルリンクをクリックする。
2. URLパラメータから申請番号を取得する。
3. アクセス権限チェックを行う。
4. DBから申請書詳細データを取得する。
5. 申請詳細画面を表示する。

### 出力・結果
申請詳細画面に以下を表示する：

- 申請番号・申請種別・申請タイトル
- 申請金額・申請理由・申請日
- ステータス・承認者
- 添付ファイル一覧（ダウンロードリンク付き）
- 承認履歴（F-015参照）
- 操作ボタン（ステータスに応じて表示制御）

### エラー条件

| エラー | メッセージ |
|-------|----------|
| 申請書不存在 | 「指定された申請書が見つかりません」 |
| アクセス権限なし | 「この申請書を参照する権限がありません」 |

## F-010: 承認者による承認処理

### 概要
承認者が承認待ち状態の申請書を承認する機能。

### 前提条件
- 承認者（課長または部長）がログイン済みであること。
- 対象申請書のステータスが「承認待ち」であること。
- ログインユーザーが対象申請書の承認者として設定されていること。

### 入力

| 項目 | 型 | バリデーション |
|-----|---|--------------|
| 承認コメント | 文字列 | 任意、最大500文字 |

### 処理内容

1. 承認者が申請詳細画面で「承認」ボタンをクリックする。
2. 承認確認ダイアログを表示する。
3. 承認者が確認し「確定」をクリックする。
4. 申請書ステータスを「承認済み」に更新する。
5. 承認日時・承認者・承認コメントを承認履歴に記録する。
6. 申請者へメール通知を送信する（F-014参照）。
7. 申請詳細画面に「承認しました」メッセージを表示する。

### 出力・結果
- 申請書ステータスが「承認済み」に更新される。
- 承認履歴に記録される。
- 申請者へ承認通知メールが送信される。

### エラー条件

| エラー | メッセージ |
|-------|----------|
| 承認権限なし | 「この申請書を承認する権限がありません」 |
| ステータス不正 | 「承認待ち状態の申請書のみ承認できます」 |

---

## F-011: 承認者による差し戻し処理

### 概要
承認者が承認待ち状態の申請書を差し戻す機能。

### 前提条件
- 承認者（課長または部長）がログイン済みであること。
- 対象申請書のステータスが「承認待ち」であること。
- ログインユーザーが対象申請書の承認者として設定されていること。

### 入力

| 項目 | 型 | バリデーション |
|-----|---|--------------|
| 差し戻しコメント | 文字列 | **必須**、最大500文字 |

### 処理内容

1. 承認者が申請詳細画面で「差し戻し」ボタンをクリックする。
2. 差し戻し理由入力ダイアログを表示する。
3. 承認者が差し戻しコメントを入力し「確定」をクリックする。
4. 申請書ステータスを「差し戻し」に更新する。
5. 差し戻し日時・差し戻し者・コメントを承認履歴に記録する。
6. 申請者へメール通知を送信する（F-014参照）。
7. 申請詳細画面に「差し戻しました」メッセージを表示する。

### 出力・結果
- 申請書ステータスが「差し戻し」に更新される。
- 承認履歴に記録される。
- 申請者へ差し戻し通知メールが送信される。

### エラー条件

| エラー | メッセージ |
|-------|----------|
| 差し戻しコメント未入力 | 「差し戻し理由を入力してください」 |
| 承認権限なし | 「この申請書を差し戻す権限がありません」 |
| ステータス不正 | 「承認待ち状態の申請書のみ差し戻しできます」 |

## F-012: 申請者による申請取り消し

### 概要
申請者が自身の申請書を取り消す機能。

### 前提条件
- 申請者本人がログイン済みであること。
- 対象申請書のステータスが「下書き」または「承認待ち」または「差し戻し」であること。

### 入力

| 項目 | 型 | バリデーション |
|-----|---|--------------|
| 取り消し理由 | 文字列 | 任意、最大500文字 |

### 処理内容

1. 申請者が申請詳細画面で「取り消し」ボタンをクリックする。
2. 取り消し確認ダイアログを表示する（「この操作は取り消せません」旨を明示）。
3. 申請者が確認し「確定」をクリックする。
4. 申請書ステータスを「取消」に更新する。
5. 取り消し日時・取り消し理由を記録する。
6. 承認者へメール通知を送信する（承認待ち状態の場合のみ）。
7. 申請一覧画面へリダイレクトし「申請を取り消しました」メッセージを表示する。

### 出力・結果
- 申請書ステータスが「取消」に更新される。
- 承認待ち状態だった場合、承認者へ取り消し通知メールが送信される。

### エラー条件

| エラー | メッセージ |
|-------|----------|
| 取り消し権限なし | 「この申請書を取り消す権限がありません」 |
| ステータス不正 | 「承認済みの申請書は取り消しできません」 |

## F-013: 申請ステータス管理（遷移定義）

### 概要
申請書のステータスと遷移ルールを定義する。

### ステータス一覧

| ステータス | 説明 |
|----------|-----|
| 下書き | 申請書作成中。未提出状態 |
| 承認待ち | 申請書提出済み。承認者の処理待ち |
| 承認済み | 承認者が承認した最終状態 |
| 差し戻し | 承認者が差し戻した状態。申請者が再編集可能 |
| 取消 | 申請者が取り消した最終状態 |

### ステータス遷移図

```
[下書き] ──提出──→ [承認待ち]
                       │
              ┌────────┼────────┐
           承認       差し戻し    取消
              │         │         │
              ↓         ↓         ↓
          [承認済み]  [差し戻し]  [取消]
                         │
                    再提出（編集後）
                         │
                         ↓
                      [承認待ち]
```

### 遷移ルール

| 現在のステータス | 操作 | 遷移先 | 実行者 |
|--------------|-----|-------|-------|
| 下書き | 提出 | 承認待ち | 申請者 |
| 下書き | 取り消し | 取消 | 申請者 |
| 承認待ち | 承認 | 承認済み | 承認者 |
| 承認待ち | 差し戻し | 差し戻し | 承認者 |
| 承認待ち | 取り消し | 取消 | 申請者 |
| 差し戻し | 再提出 | 承認待ち | 申請者 |
| 差し戻し | 取り消し | 取消 | 申請者 |
| 承認済み | （操作不可） | - | - |
| 取消 | （操作不可） | - | - |

### エラー条件

| エラー | メッセージ |
|-------|----------|
| 不正な遷移 | 「現在のステータスではこの操作は実行できません」 |

---

## F-014: メール通知

### 概要
申請ステータスの変更時に関係者へメール通知を送信する機能。

### 前提条件
- システムのSMTP設定が完了していること。
- 通知対象ユーザーのメールアドレスが登録済みであること。

### 通知トリガーと送信先

| トリガー | 送信先 | 件名 |
|---------|-------|-----|
| 申請提出 | 承認者 | 【承認依頼】{申請タイトル} |
| 承認 | 申請者 | 【承認完了】{申請タイトル} |
| 差し戻し | 申請者 | 【差し戻し】{申請タイトル} |
| 取り消し（承認待ち） | 承認者 | 【取り消し】{申請タイトル} |

### 処理内容

1. ステータス変更イベントが発生する。
2. 通知テンプレートを選択する。
3. メール本文を生成する（申請番号・タイトル・ステータス・申請詳細URLを含む）。
4. SMTPサーバーへメール送信要求を行う。
5. 送信結果をログに記録する（成功・失敗問わず）。
6. 送信失敗時はリトライキュー（最大3回）に追加する。

### 出力・結果
- 通知メールが送信される。
- 送信ログがDBに記録される。

### エラー条件

| エラー | 対応 |
|-------|-----|
| SMTP接続失敗 | リトライキューに追加（最大3回）、失敗ログを記録 |
| 宛先メール不正 | 送信スキップ、エラーログを記録 |

---

## F-016: CSVエクスポート

### 概要
申請一覧をCSVファイルとしてエクスポートする機能。

### 前提条件
- ユーザーがログイン済みであること。
- 管理者または課長・部長権限を持つユーザーであること。

### 入力
- 申請一覧の検索条件（F-008参照）

### 処理内容

1. ユーザーが申請一覧画面で「CSVエクスポート」ボタンをクリックする。
2. 現在の検索条件で対象データを取得する（最大10,000件）。
3. CSVファイルを生成する（文字コード: UTF-8 BOM付き）。
4. ファイル名: `applications_YYYYMMDD_HHMMSS.csv`
5. ブラウザへファイルダウンロードを開始する。

### 出力・結果
- CSVファイルがダウンロードされる。
- CSVには以下の列を含む: 申請番号、申請種別、申請タイトル、申請金額、ステータス、申請者名、承認者名、申請日、承認日

### エラー条件

| エラー | メッセージ |
|-------|----------|
| 権限なし | 「CSVエクスポートの権限がありません」 |
| 件数超過 | 「エクスポート対象が10,000件を超えています。条件を絞り込んでください」 |

## F-019: パスワード変更

### 概要
ログイン中のユーザーが自身のパスワードを変更する機能。

### 前提条件
- ユーザーがログイン済みであること。

### 入力

| 項目 | 型 | バリデーション |
|-----|---|--------------|
| 現在のパスワード | 文字列 | 必須 |
| 新しいパスワード | 文字列 | 必須、8文字以上、英数字混在、現在のパスワードと異なること |
| 新しいパスワード（確認） | 文字列 | 必須、新しいパスワードと一致 |

### 処理内容

1. ユーザーが「パスワード変更」メニューをクリックする。
2. パスワード変更フォームを表示する。
3. 各項目を入力し「変更」ボタンをクリックする。
4. 現在のパスワードの照合を行う。
5. 新しいパスワードのバリデーションを実施する。
6. 新しいパスワードをハッシュ化してDBを更新する。
7. 既存セッションを全て無効化する（セキュリティ対策）。
8. ログイン画面へリダイレクトし「パスワードを変更しました。再度ログインしてください」メッセージを表示する。

### 出力・結果
- パスワードが更新される。
- 全セッションが無効化される。
- ログイン画面へ遷移する。

### エラー条件

| エラー | メッセージ |
|-------|----------|
| 現在のパスワード不一致 | 「現在のパスワードが正しくありません」 |
| 新パスワード強度不足 | 「パスワードは8文字以上で英字と数字を含めてください」 |
| 新パスワード一致なし | 「新しいパスワードが一致しません」 |
| 同一パスワード | 「新しいパスワードは現在のパスワードと異なるものを設定してください」 |

## F-020: システム設定（管理者機能）

### 概要
管理者がシステム全体の設定を管理する機能。

### 前提条件
- 管理者権限を持つユーザーがログイン済みであること。

### 入力

| 項目 | 型 | バリデーション |
|-----|---|--------------|
| SMTPサーバー | 文字列 | 必須、ホスト名形式 |
| SMTPポート | 数値 | 必須、1〜65535 |
| SMTPユーザー名 | 文字列 | 必須 |
| SMTPパスワード | 文字列 | 任意（未変更の場合は空白） |
| 送信元メールアドレス | 文字列 | 必須、メール形式 |
| アカウントロック閾値 | 数値 | 必須、1〜10の整数 |
| セッションタイムアウト | 数値 | 必須、5〜480分 |

### 処理内容

1. 管理者が「システム設定」メニューをクリックする。
2. 現在のシステム設定を取得して設定画面を表示する。
3. 設定値を変更し「保存」ボタンをクリックする。
4. バリデーションを実施する。
5. 設定値をDBに保存する。
6. 「システム設定を保存しました」メッセージを表示する。
7. メール設定変更時は「テスト送信」ボタンで疎通確認ができる。

### 出力・結果
- システム設定が更新される。
- 設定変更は即時反映される。

### エラー条件

| エラー | メッセージ |
|-------|----------|
| 権限なし | 「システム設定の権限がありません」 |
| SMTP接続テスト失敗 | 「SMTPサーバーへの接続に失敗しました。設定を確認してください」 |
| 値範囲外 | 「{項目名}の値が不正です」 |
