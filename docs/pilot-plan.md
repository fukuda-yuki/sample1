# 校正から初期反復まで

1. 校正（calibration）: 採点器を妥当な参照fixtureで受入、閾値だけを変えたmutationで検出確認。総トークン計測と0点・満点・失敗・blocked・評価不能・usage欠測の集計を検証する。合成入力・校正fixtureは比較データにしない。
2. パイロット（pilot）: normal/anti各1 Run。新規セッションから開始し、隔離→実装→停止→固定→usage→独立採点→図の全経路を接続する。差の有無や大きさは開始・継続条件にしない。
3. 比較（comparison）: 同じ版で各条件3 Run。各ペア内の順序を無作為化し、順序manifestを入力・評価結果を見る前に固定する。pilotは同じ版でもcomparisonと区別して描く。
4. 観測後: F-006に達しないほど環境構築・全20機能が重ければ環境改善・共通骨格・課題縮小をユーザーへ具体案として提示する。新しい実験版に分け、旧データを削除・単純合算しない。

## 比較開始ゲート

- 配布許可リスト・履歴・外部通信を含め情報漏洩がない実環境を確認済み。
- 共通指示から未配布ファイル参照を除去済み、意図したAP-001差分を保護。
- 採点器が正常解を受入、閾値mutationを検出。未提示UI差で誤判定しない。
- 小さな実Runでusage原本と正規化総量を照合し、欠測・二重計上を識別可能。
- 親子停止・成果物固定・固定分母57・終了理由を保存できる。
- モデル・effort・上限・回数・評価単位はdecision-logのユーザー確定値。

ゲートに実測根拠がない状態をreadyとしない。校正の実施はゲート未達でも可。各ゲートの根拠はGitHub #11へ記録する。

## Runと版

各Runにphase、condition、順序、Run ID、experiment_version、spec/共通指示hash、モデル・effort、agent/tool/image版、終了理由、submission_hash、usage完全性、採点版・評価ID別結果を保存する。通常終了だけを選ばない。

再実装は新Run IDとrerun_of。評価器だけの修正は同じ固定提出物の新採点実行IDとし、両条件へ適用する。失敗や上限到達は元記録を残す。測定不備と意図的条件変更をdecision-logで区別する。

無差・逆方向の差・欠測を含め全Runを提示する。初期反復だけで必要標本数や一般的効果を確定しない。主張はこの1アプリ・AP-001・当該エージェント構成の探索結果に限る。
