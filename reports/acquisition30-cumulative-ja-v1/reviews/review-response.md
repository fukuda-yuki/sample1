# 独立レビューへの対応

レビューは完成した科学的本文・図表・データを、執筆履歴を共有しない別コンテキストへ渡して実施した。指摘を受けた後の修正と再確認を以下に残す。研究アプリやv6は再実行せず、保存された原本は変更していない。

| 指摘 | 対応 | 確認対象 |
| --- | --- | --- |
| 冒頭の「事前に指定した13評価ID」は、旧20件にも事前固定だったように読める。 | 「追加取得前に分類を固定した13評価ID」へ変更。方法と考察では旧20件に対する事後分類、新40件に対する事前固定を引き続き区別。 | 本文冒頭・第2節・第4節。 |
| 元usageの完全性が本文から把握しにくい。 | usage_complete=falseを累計18/60、通常12/30、不整合6/30と方法へ追記。記録済み合計を維持し、元フラグを変更していない。 | SQL C02、Run別データ。 |
| 考察の分量が読み物部分の約28%にとどまる。 | 平均低下と中央値上昇を両立させる分布の解釈、欠測による対象の違い、反復数と評価妥当性の区別を追加。第1〜4節の表・図・見出しを除く文字数で約32.5%となった。 | 第4節。新しい数値集計やデータ選別は加えていない。 |
| normal-001の起動失敗に対応するログはstdoutだけでは不足する。 | 元stdout参照を保持し、ENOTCACHEDとVite 5.4.2を含むstderrの参照、hash、1・2行目の位置を追加。私自身も原本を読んで照合。 | OBS-new-normal-001-startup、app-logs.stderr.log SHA256 `dcead26833a1f8d77362af6e0427ae9e5b458f84af3fa3a98dc2acd0e5a477b2`。 |
| 追加した欠測の考察が、欠測機序を断定する表現になっている。 | 「起動不能による欠測が無作為とは仮定しない」へ変更。3件だけから統計的な欠測機序を確定していないことを明確にした。 | 第4節の対象数・欠測の段落。 |

stderr参照の追加によって読解記録のhashが変わるため、分析JSONの証拠束縛、SQL結果、図の出典記録、補足を再生成した。統計値・個別合否・記録済みトークンは変わっていない。開始していた旧参照版の累計復元確認は中止の記録を残し、修正版で再度実施した。これは保存データを使う再集計であり、新規実装や再採点ではない。

最終の独立再確認は[independent-recheck.md](independent-recheck.md)を参照。受入確認と公開の完了状況は本文第6節と`checks`へ記録する。
